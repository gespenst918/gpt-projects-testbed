## How to use this repository
1. Open the relevant project README.
2. Record the next concrete task in a GitHub Issue, linking to that project.
3. Save useful conclusions as Markdown (.md) files: simple text documents GitHub displays as formatted pages.
4. Keep sources, assumptions, proposals, and confirmed decisions distinct.
5. Update the project status and next step when work changes.

Use short, descriptive, lowercase filenames with hyphens. Write in the language most useful for the audience; label translated versions with -en, -ja, or -zh when needed.

Methods belong in projects/ways-and-means; market-specific evidence belongs in knowledge. Link between them instead of duplicating content.

Store client-confidential records, payroll, personal correspondence, and credentials outside this general hub. Repository folders do not provide separate access permissions. Mature applications may have separate repositories linked from their project README.
